# Phase 6: PR Assembly - Implementation Documentation

## Overview

The PR Assembly phase is the final phase in the PatchPilot AI pipeline. It takes validated fixes from Phase 5 and assembles them into a complete, production-ready Pull Request package with comprehensive documentation, testing instructions, and metadata.

## Location

- **File**: `lib/pipeline/phases/pr-assembly.ts`
- **Phase**: `PipelinePhase.PR_ASSEMBLY`
- **Dependencies**: Phase 5 (Validation)

## Key Features

### 1. Comprehensive PR Documentation

The phase generates a complete PR description with:

- **Overview Section**: Root cause analysis, error context, and severity
- **Changes Summary**: High-level summary of all modifications
- **Detailed Explanation**: AI-generated explanation of the fix approach
- **Validation Results**: Test results, lint scores, security scan results
- **Quality Metrics**: Maintainability, readability, complexity scores
- **Detailed Changes**: File-by-file breakdown with diffs and explanations
- **Breaking Changes**: Warnings about API changes with mitigation strategies
- **Testing Instructions**: Step-by-step guide to verify the fix
- **Rollback Instructions**: Commands to revert changes if needed
- **Checklist**: Pre-merge verification items

### 2. Smart PR Title Generation

Generates concise, semantic PR titles:
- Uses root cause analysis when available
- Follows conventional commit format (`fix(category): description`)
- Truncates to appropriate length
- Falls back to generic titles when needed

### 3. Intelligent Labeling

Automatically generates labels based on:
- Issue category (bug, feature, refactor, etc.)
- Severity level
- Programming language
- Quality score (high/medium/low quality)
- Breaking changes flag
- Test coverage flag

### 4. Branch Naming

Generates semantic branch names:
- Format: `patchpilot/{category}-{timestamp}`
- Sanitized for git compatibility
- Unique per execution

### 5. Confidence Scoring

Calculates overall confidence based on:
- Average fix confidence (40% weight)
- Root cause confidence (20% weight)
- Validation quality score (40% weight)

### 6. Reviewer Suggestions

Prepares infrastructure for suggesting reviewers based on:
- File ownership (via git blame)
- CODEOWNERS file parsing
- Historical contribution patterns

## Usage Example

```typescript
import { createPRAssemblyPhase } from './lib/pipeline/phases/pr-assembly';
import { PhaseRegistry } from './lib/pipeline/core/phase-registry';

// Create and register the phase
const prAssemblyPhase = createPRAssemblyPhase({
  timeout: 60000,  // 1 minute
  maxRetries: 2,
});

const registry = PhaseRegistry.getInstance();
registry.registerPhase(prAssemblyPhase);

// Execute through pipeline context
const result = await prAssemblyPhase.execute(context);

if (result.success && result.data) {
  const { prPackage, summary } = result.data;
  
  console.log('PR Title:', prPackage.title);
  console.log('Branch:', prPackage.branchName);
  console.log('Confidence:', prPackage.confidence);
  console.log('Labels:', prPackage.labels.join(', '));
  console.log('\nSummary:', summary);
  
  // Use prPackage to create actual GitHub PR
  // await createGitHubPR(prPackage);
}
```

## Error Handling

The phase handles errors gracefully:

- **Missing Fixes**: Validates that at least one fix exists
- **Missing Validation**: Ensures validation output is present
- **Invalid Repository**: Checks repository metadata
- **Formatting Errors**: Catches markdown generation issues

Error handling strategy: `FAIL` (non-transient errors fail the pipeline)

### Output for GitHub Integration

The `PRPackage` is designed to map directly to GitHub API calls:

```typescript
// Example GitHub API integration
async function createGitHubPR(prPackage: PRPackage, repoInfo: RepoInfo) {
  const octokit = new Octokit({ auth: process.env.GITHUB_TOKEN });
  
  // Create branch
  await createBranch(octokit, repoInfo, prPackage.branchName);
  
  // Commit changes
  for (const change of prPackage.changes) {
    await commitFile(octokit, repoInfo, change);
  }
  
  // Create PR
  const pr = await octokit.rest.pulls.create({
    owner: repoInfo.owner,
    repo: repoInfo.name,
    title: prPackage.title,
    body: prPackage.description,
    head: prPackage.branchName,
    base: repoInfo.branch,
  });
  
  // Add labels
  await octokit.rest.issues.addLabels({
    owner: repoInfo.owner,
    repo: repoInfo.name,
    issue_number: pr.data.number,
    labels: prPackage.labels,
  });
  
  return pr.data;
}
```
